# 序言：软件应当是体系结构世界的中央

世界上最重要的硬件——中央处理器，已经是图灵完备的了。任何一种新的数字集成电路，都不能在可计算性上有新的突破。大部分的创新目的在于性能，功耗，成本等等商品化的面向市场和应用测的指标。这其中又以性能为重点。换言之绝大部分体系结构创新是纯正的工程创新，需要面对市场份额的审判。

史上有无数的创新试图撼动x86指令的中央处理器在高性能计算领域的份额。然而除了英伟达的GPU，其余的全部都失败了。这些新的创新包括新的技术路线比如FPGA，CGRA, VLIW, 数据流式指令集，甚至包括各种ASIC, NPU;也包括某种现有路线下的新产品比如RISC-V，有相对好结果的是蜷缩在市场的一个不起眼的角落里面服务于某种小众需求，不好的则破产清算湮没在历史的尘烟里。这些创新中的每一个都可以宣称自己对传统的产品实现了某种性能指标上的赶超，甚至是颠覆式的大幅度赶超。但是除了唯一的例外，每一个路线的市场结局都不算特别理想。这样的例子如此之多，以至于我们面对一个新的路线，不太用了解它的任何细节，只需要躺在床上猜它会扑街，大概率没错。

为什么它们都没有能力成为市场的主流？

被提到最多的原因是关于软件的。比如编译器没有能力为超长字指令寻找足够填充流水线的指标；编译器没法自动的高效的程序转换成某种电路结构落实在FPGA上；我们的新指令集明明很优越，但是没有人愿意为它迁移编译器；我们的NPU能效面效显著的高过GPU，但是客户不愿意花费他们高贵的精力将他们的CUDA CPP或者pytorch迁移到我们的产品上；英伟达的CUDA真是太厉害啦呢(不只一次听到这句话)，我们没法战胜它哦；

那么既然这么多原因都是关于软件的。那么在体系结构的世界里面有关软硬件配合的知识和理论，一定是极度不平凡并且值得深入思考和探讨的。也许它的重要性要远超过对硬件的任何一个具体的主题比如片上网络或者浮点单元的设计的讨论。在这个主题上，我想泛泛而谈是远远不够的。我们需要更严格更深入的知识框架，以及如果可能的话，对某些问题进行定量分析。

故事开始于一个基本数量级估计，我检索到的资料显示全世界有大约2000-2900万的职业程序开发者，而他们的平均统计薪酬是10万美元左右。假定他们的人力成本构成了软件开发的全部。那么人类每年在软件开发上投入的成本量级约为3万亿美元。而全球十大IC设计公司的总营收约为2500亿美元量级。而全球硬件的研发年成本没有精确数据，但是有估计为300-500亿美元量级。人类设计软件所投入的总和成本和人力高于硬件总和人力成本一到两个数量级。按照朴素的直觉，高性能数字集成电路的设计是人类科技的天花板之一，是最为昂贵和复杂的造物。而软件不过只是大一新生或者java培训班中专生都可以掌握的常规手艺。但是事实证明软件的成本和复杂度才是真正的庞然巨物。

从这样的讨论中我们就立刻可以得出一个看上去很平凡又很粗糙的一头兔子定律： 

$$\text{体系结构创新的价值} = \text{单位算力的边际价值} \times \text{单位算力提升} - \text{对软件系统价值的伤害}$$

$$\text{体系结构创新的成本} = \text{硬件的研发和流片等一次性成本} + \text{适配新体系结构的软件系统的开发成本}$$

一头兔子定律不仅十分粗糙，比如体系结构创新的价值也许表现为功耗缩减，或者单位性能的成本缩减，而且它也非常平凡，看上去仅仅是罗列一些显然的事实之后做了一点小盆友都会算的四则运算。但是结合了上面的数量级估计，它在很认真的讲一个被很多人类忽略的常识，软件系统的成本并不是一个可以忽略的小量。相反，它在很多场景中是效益和成本的中央。如果一个体系结构的硬件创新的代价是剧烈的毁灭旧软件的价值，或者说是剧烈提高了新软件的开发成本，那么它的实际的商业价值可能是事实上的负数。

总的而言还是过于空泛的讨论。

为了进一步深入的讨论我需要两种工具，第一，如果我们的目的是通过软件的视角分析体系结构的商业价值得失，也许我们可以讲商业价值简化成一个成本与收益的模型。假如一个创新将面向软件侧的复杂度和性能放在天平两端，那么我们可以计算性能提升带来的商业价值，以及软件开发成本上升带来的商业损失，然后简单做差或者做除法来评估它是够合适。有了具体的计算方法，我们就可以做具体的计算，评估一个创新是否值得，而非仅仅坐而论道。比如NPU流水线应该依赖于SMT的硬件自动并行去填满，还是要软件侧手工去填满它？

第二，我需要画出软件和硬件系统作为一个整体的结构。信息技术行业习惯于为复杂系统分层，最常见的例子是计算机网络的层次结构，其次操作系统也可以分层次结构。计算机体系结构专业的人见过存储器时延与容量的层次结构。我可以模仿这一传统可以将软件和硬件构成的满足用户需求的复杂整体划分出某种层次结构。这种划分对于讨论是必须的，将软件作为一个庞大的整体切割的更加细小，才有可能讨论更精细的信息。

# 别名模型： 树状抽象域

某种意义上是LLVM的TBAA和 MLIR 的 scoped alias/noalias混合。它本身具有两可性，既是一个面向上层编译器和程序员的hint接口，也是编译器做别名分析时依赖的专属类型系统(Domain-Specific Type System)。它是一套依赖集合与格运算的框架。

## 抽象域

别名分析的基础概念是抽象域，抽象域可以并不意味着一块连续的内存，而仅是一种抽象的概念。比如全体堆中内存构成的域或者全体双精度浮点数指针指向构成的域，这个两个域并意味着两块连续的内存，一个指针可以同时属于两个域。域是一种特殊的集合，有从属关系，可以进行相交相并的运算。

在本模型中，全体域都从属一个树状关系，编译器自动为这颗树生成统一的虚拟根。树状关系自动表达了从属，一个节点对应必然属于它的父节点。属于关系是一种偏序，是自反传递的。所以全部的抽象域构成了一个半格。我们设计的核心因素之一就是，并不假定一个父节点下属的全体子节点相交非空或者说它们是否互斥。




举个例子，虚拟根节点，可以下属类型子树，和域子树。类型子树和域子树，可以是相交的，并不互斥。一个指针可以是双精度浮点的堆中指针。那么需要一种语法传达这种互斥关系，最符合直觉的是把类型子树分为四类。分别是强互斥，弱互斥，弱相交，强相交。

|   相交关系  | 强互斥 | 弱互斥 | 弱相交 | 强相交 |
|----------- |--------|-------|--------|-------|
|    强互斥   |    N   |   N   |   N   |    N   |
|    弱互斥   |    N   |    N  |   ?   |    T  |
|    弱相交   |    N   |   ?   |     T  |     T   |
|    强相交   |    N   |   T   |    T  |     T  |


可以简单的列出关系表格，表格中的大部分项目都很容易填写，问题在于弱互斥和弱相交是否的关系。如果它是T,那么意味着强弱相交关系是冗余的，只需要一种就可以了。

|   相交关系  | 强互斥 | 弱互斥 | 弱相交 | 强相交 |
|----------- |--------|-------|--------|-------|
|    强互斥   |    N   |   N   |   N   |    N   |
|    弱互斥   |    N   |    N  |   T   |    T  |
|    弱相交   |    N   |   T   |     T  |     T   |
|    强相交   |    N   |   T   |    T  |     T  |

等价于

|   相交关系  | 强互斥 | 弱互斥 | 相交 | 相交 |
|----------- |--------|-------|--------|-------|
|    强互斥   |    N   |   N   |   N   |    N   |
|    弱互斥   |    N   |    N  |   T   |    T  |
|    相交   |    N   |   T   |     T  |     T   |
|    相交   |    N   |   T   |    T  |     T  |

### 问题

但是问题还没有结束，如果一个元素被设定为非的关系，那么它相交自身为空，相交其他所有同母节点的抽象域不空，两个非的相交，如果它俩的并是父节点，那么是无交的，否则是相交的。那么设定两个子集相并是否是父节点的规则就可以了。事实上我们默认每种子集都是有自身独占的元素，所以并集等于父级，当且仅当两者是父级的唯二子集。

### 全集策略

如果一些非操作集合判断是否相交，那么我们可以使用德摩根律，将这些集合的非的交变成并集的非。此时我们需要一套判断并集是否是某个父级的全集的机制。



此外一个关键的权衡是用户或者编译器能否主动突破上文的表格的约束，把表格的内容当作默认值，自行设置两个关系是否相交。作者还没有能力想明白这一点。可能最好的做法是，在默认规则中相交非空的两个抽象域，可以通过额外规则把它们的相交设定为空。反之，在默认规则中相交为空的两个抽象域，不能使用额外规则把它们设置为相交不为空。此外用户可以把某个集合的独占元素设置为空吗？

## 运算规则和实例

首先，这套规则的核心在于证明两个变量所属的域是无交的，如果能证明无交，那么说明两个指针不会重名。如果由于编译器运行时限或者说编译器策略有限，无法证明是无交的，那么等同于可能别名的相交。保守的判断两个无交的集合是可能相交的，换言之没有证明无交，那么这种保守不会引起错误。



比较相交非空的算法是讲两个抽象域提升到同一个父节点的子节点后，比较这两个子节点是否是相交的。如果一个非的集合被提升了任意一次，它的非运算符号直接消失。




一个指针类型可以按照C语言风格的交并非的集合运算指定它从属的虚拟集合，最终在比较的时候会把这种关系转换为析取范式。如果两个指针的任意析取分支是相交的，那么这两个指针有可能能指向相同的地址，换言之可能存在别名。下面是个例子alias前的叹号，表示工具链强注释的开头，和集合运算无关:

```
ptr-!alias[ !int && !heap ] ptr_1;
ptr-!alias[ (int && stack) || (real && heap)] ptr_2;

ptr-!alias[ int ] ptr3;
ptr-!alias[ stack] ptr4;
```

其中`ptr1` 所属的集合和`ptr2`无交。但是`ptr3`和 `ptr4`相交，可能存在别名。

### 问题

但是任意两个析取分支判断是否相交需要新的规则，三个集合两两相交并不能判断它们三个是否相交为空。这是这套系统在设计上面临的最大问题。此时最大的保护在于懒策略，把三个两两相交的集合但是实际无交的集合判定为相交，不会引起错误。

补集运算应当是根节点中还是父节点中。

父节点中的优势是语法糖感更重。缺点是运算更麻烦。

```
ptr-!alias[ !int && !heap ] ptr_1;
ptr-!alias[ (!int && type) && (!heap && scope)] ptr_1;
```

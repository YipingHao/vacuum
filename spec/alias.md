# 别名模型： 树状抽象域

某种意义上是LLVM的TBAA和 MLIR 的 scoped alias/noalias混合。它本身具有两可性，既是可以用作面向上层编译器和程序员的hint接口，也可以用作编译器做别名分析时依赖的专属类型系统(Domain-Specific Type System)。不过本规范仅仅指定它用作Hint接口，是否成为优化器的某一个实现真正采用的专属类型系统则不做规定。它是一套依赖集合与格运算的框架。

## 抽象域

别名分析的基础概念是抽象域，抽象域可以并不意味着一块连续的内存，而仅是一种抽象的概念。比如全体堆中内存构成的域或者全体双精度浮点数指针指向构成的域，这个两个域并意味着两块连续的内存，一个指针可以同时属于两个域。域是一种特殊的集合，有从属关系，可以进行相交相并的运算。本文中，相交非空被简称为相交。

在本模型中，全体域都从属一个树状关系，编译器自动为这颗树生成统一的虚拟根。树状关系自动表达了从属，一个节点对应必然属于它的父节点。属于关系是一种偏序，是自反传递的。所以全部的抽象域构成了一个半格。我们设计的核心因素之一就是，并不假定一个父节点下属的全体子节点相交非空或者说它们是否互斥。举个例子，虚拟根节点，可以下属类型子树和域子树。类型子树和域子树，可以是相交的，并不互斥。一个指针可以同时是双精度浮点的堆中指针。

## 节点属性

既然全体抽象域之间存在一个树状关系，我们也可以称每个**抽象域**为**节点**。我们的抽象规则规定，每一个节点必须通过一个关键字设定与它的兄弟的节点的关系。这种关系名字叫做**互斥属性**。互斥属性分为四类，分别是：强互斥，弱互斥，弱相交，强相交。某一个节点A与它的兄弟节点B相交是否非空，几乎由这两个节点的互斥属性决定。它们相交运算的结果如下。

|   相交关系  | 强互斥 | 弱互斥 | 弱相交 | 强相交 |
|----------- |--------|-------|--------|-------|
|    强互斥   |    N   |   N   |   N   |    N   |
|    弱互斥   |    N   |   N  |   N   |    T  |
|    弱相交   |    N   |   N   |   T   |     T  |
|    强相交   |    N   |   T   |    T  |     T  |


- 任意基本节点相交运算规则：互斥属性决定了任意两个节点的基本运算规则：如果两个集合A与B没有从属于同一个父节点，那么逐级向上寻找它们的深度最小的公共祖先C。随后找到公共祖先C的全体子节点中这两个集合各自的祖先节点D与E。 D与E的相交结果就是A与B相交的结果。

- 全集规则: 假定每一个集合都有自身独占，不属于兄弟节点的内部。所以一些兄弟节点的并集是父节点，当且仅当并集运算包含了全部的兄弟节点。



## 建立抽象域构成的树

通过 `#AliasTree`指令建立抽象树的节点。语法规则如下 `#AliasTree(name_id, parent_id, attri_id)`。这种建立规则仅仅能出现在函数定义之间。

`name_id`是节点名标识符，这棵树的任意两个节点不得重名。根节点的名字为`AliasRoot`,此外编译器会自动为这个根生成一个虚拟的父节点`AliasRootRoot`。根节点的虚拟父节点是为了简化实现程序的复杂度，有些判断需要提升到根节点，此时如果它有一个父节点，那么可以用同一套逻辑处理根节点和用户自定义节点。所以编译器和程序员手工添加的新节点均不得与上述两节点重名。`parent_id`指定父节点标识符，而`attri_id`决定了它的互斥属性，四个属性对应的标识符分别为。

- 强互斥，`Exclusive`
- 弱互斥，`WeakExclusive`
- 弱相交，`WeakInclusive`
- 强相交, `Inclusive`

例子 

```
#AliasTree(type, AliasRoot, Inclusive)
#AliasTree(scope, AliasRoot, Inclusive)

#AliasTree(int, type, WeakExclusive)
#AliasTree(float, type, WeakExclusive)
#AliasTree(void, type, Inclusive)

#AliasTree(int64, int, WeakExclusive)
#AliasTree(intDefault, int, Inclusive)
#AliasTree(int32, int, WeakExclusive)

#AliasTree(float64, float, WeakExclusive)
#AliasTree(floatDefault, float, Inclusive)
#AliasTree(float32, float, WeakExclusive)

#AliasTree(stack, scope, WeakExclusive) 
#AliasTree(heap, scope, WeakExclusive)

#AliasTree(restrict, AliasRoot, Exclusive)
```


### 规定指针从属的域

指针所属的抽象域通过特定的工具链注释来规定。该注释以通用符号 `-!` 开头，后接关键字 `alias`（在Vacuum的语法规范中它实际是个标识符），最后用方括号 `[]` 包裹描述域的规则体。完整的格式为 `-!alias[rules]`，其中方括号是强制性的。

规则体采用类C语言的集合运算语法来定义指针所属的虚拟集合，支持使用小括号 `()` 明确运算优先级：
*   **与运算** `&&` 表示集合的**交集**。
*   **或运算** `||` 表示集合的**并集**。
*   **非运算** `!` 应用于单个节点，表示该节点在**整个抽象域树的根节点（AliasRoot）** 中的补集（请注意，不是其直接父节点）。

运算符优先级与C语言规定一致。以下是指针声明的示例：

```c
ptr-!alias[ (!int && type) && (!heap && scope) ] ptr_1;
ptr-!alias[ (int && stack) || (float && heap) ] ptr_2;

ptr-!alias[ int ] ptr3;
ptr-!alias[ stack ] ptr4;
```


下表是C语言中这三个逻辑运算符的优先级和结合性。

| 运算符 | 名称 | 优先级 | 结合性 |
| :--- | :--- | :---: | :---: |
| **`!`** | 逻辑非 | 最高 | 从右到左 |
| **`&&`** | 逻辑与 | 居中 | 从左到右 |
| **```\|\|```** | 逻辑或 | 最低 | 从左到右 |


### 空集的表示

空集是本系统中的一个基础概念。**两个默认规则下互斥的集合，它们的交集即为空集**。例如，根据互斥属性表，任何集合与“强互斥”集合的交集都为空集。 在别名判断中，如果一个指针的域被定义为两个互斥域的“与”操作（如 `int && float`），且根据规则它们的交集为空，则该指针的从属域为空集。本规则没有显式指定空集的语法。

### 根节点默认规则

- **空规则体**：当规则体为空（即 `-!alias[]`）时，该指针被解释为从属于**根节点（AliasRoot）**。这是基于安全性优先的保守性原则，确保不会因疏忽导致危险的激进优化。

- **未标注规则**：如果指针声明中**完全省略** `-!alias[...]` 注解，编译器同样应默认该指针从属于根节点。


## 通过集合运算判断指针别名


**基本规定** 两个变量所属的域是无交的，那么两个指针不会重名。

如果由于编译器运行时限或者说编译器策略有限，两个确实无交的集合如果无法证明是无交的，那么它会保守的判断两个无交的集合是可能相交的，可能出现别名。确实无交，但是编译器出于自身原因没有证明无交的，误认为相交不会引起错误，仅仅失去优化可能。

上述的例子中`ptr1` 所属的集合和`ptr2`无交。但是`ptr3`和 `ptr4`相交，可能存在别名。

一个指针如果从属虚拟集合为空集，那么它和任意其它指针所属的域都是无交的，换言之是无别名的。一个指针如果从属的虚拟集合为根节点，那么它除了和从属虚拟集合为空集指针相交为空之外，和任意其指针有交集，进而有别名。根集合的非运算指定为空集，根集合为这个上半格系统的全集。

## 运算规则

- 三大律：抽象域的运算满足集合的结合律交换律分配律。

- 德摩根律： 集合运算遵守德摩根律，这也是交换运算顺序的根本

- 升链规则： 当集合$B$是集合$A$的子集，也是两个指针从属集合的交集。那么通过判断集合$A$是否空集，代替集合$B$进行别名判断不会引起程序错误，仅仅失去优化可能。

- 补集规则：升链规则可以帮助我们计算并集的补集。如果一些兄弟节点的并集是父级，那么它们的并的补集是父节点的补集。否则那么它们在父级中的补集不一定能严格算出，但是可以轻易的找到一个包含它们的更大的集合也就是全体兄弟节点中不在这些兄弟节点的并集并上父节点补集。


最终进行别名运算的时候，会将两个集合的表达式进行交运算。把相交的结果转换为析取范式。如果任意一个析取枝是非空的，那么两个集合可能存在别名，这两个指针有可能能指向相同的地址。每个析取支内的分量化简后，两两相交，如果有一个相交是空集，那么这个析取枝可以是空集。请注意三个集合两两相交并不能判断它们三个是否相交为空。这是这套系统在设计上面临的最大问题。此时最大的保护在于懒策略，把三个两两相交的集合但是实际无交的集合判定为相交，不会引起程序错误。


## 补充规则

本规范支持补充规则，补充规则的原则是编译器忽略完全忽略编译器和用户设定的补充规则不会引起错误。

### 额外无交假定

本规范支持补充规则，其核心原则是：编译器即使完全忽略用户设定的补充规则，也不会引起分析错误。

- **保守性保证**：在默认规则中相交非空的两个抽象域，可以通过额外规则将其相交关系设定为空。反之，在默认规则中已经相交为空的两个抽象域，**不允许**通过额外规则将其设置为相交非空。这一限制确保了补充规则只能进一步严格化别名分析，而不能放松安全性约束。

- **语法格式**：使用指令 `#AliasNoIntersection(id_1, id_2)` 来声明两个抽象域 `id_1` 和 `id_2` 无交集。

#### 示例

假设已有以下抽象域定义：
```
#aliasTree(type, AliasRoot, Inclusive)
#aliasTree(int, type, WeakExclusive)
#aliasTree(float, type, WeakExclusive)

#aliasTree(scope, AliasRoot, Inclusive)  
#aliasTree(stack, scope, WeakExclusive)
#aliasTree(heap, scope, WeakExclusive)
```

根据默认的互斥属性规则，`int` 和 `stack` 域可能存在交集（即可能存在既是整型又位于栈上的指针）。

如果程序特定地保证了“整型指针绝不会指向栈内存”，则可通过补充规则声明：
```
#AliasNoIntersection(int, stack)
```

**效果**：
- 声明后，编译器可据此优化，判定属于 `int` 域的指针与属于 `stack` 域的指针绝无别名。
- 即使编译器实现选择忽略此条 `#AliasNoIntersection` 规则，它仍会按照默认的 `WeakExclusive` 属性进行可能更保守的分析，这不会导致错误的优化，只是可能错过一些优化机会。

**错误示例**（违反规范）：
```
# 错误：不能将默认无交的域声明为有交
#AliasNoIntersection(int, float) # 此声明无效且应被编译器忽略或报错
```
因为 `int` 和 `float` 节点在父节点 `type` 下均为 `WeakExclusive` 属性，根据核心规则表，它们默认已无交。此类声明被禁止，以维护整个别名分析系统的可靠性与一致性。


您提出的这两点补充非常重要，它们让规范更加严谨和实用。以下是为您补充的“错误处理”章节内容。

## 错误处理

本规范要求编译器在处理别名模型定义时，应进行必要的静态检查。一旦发现以下错误，编译器应报告错误并中止编译过程，以确保程序语义的清晰和正确。

### 编译时错误

以下情况会触发编译时错误：

| 错误类型 | 触发条件 | 示例（错误） | 说明 |
| :--- | :--- | :--- | :--- |
| **节点重名** | 使用 `#AliasTree` 指令创建了同名的节点。 | `#AliasTree(A, ...)`<br>`#AliasTree(A, ...)` | 节点标识符必须在整个树中唯一。 |
| **引用未定义父节点** | 在 `#AliasTree` 指令中，`parent_id` 指向一个未定义的节点。 | `#AliasTree(Child, UndefinedParent, ...)` | 父节点必须先行定义。 |
| **非法互斥属性** | 在 `#AliasTree` 指令中，`attri_id` 不是四个预定义的属性标识符之一。 | `#AliasTree(N, P, InvalidAttr)` | 属性必须是 `Exclusive`, `WeakExclusive`, `WeakInclusive`, `Inclusive` 之一。 |
| **指针域表达式语法错误** | `-!alias[...]` 内的集合表达式存在语法错误，如括号不匹配、使用了未定义的节点标识符或运算符错误。 | `-!alias[ (int && stack ] ptr;` （括号不匹配）<br>`-!alias[ unknownNode ] ptr;` （节点未定义） | 表达式必须符合规定的类C语法。 |
| **补充规则冲突** | 使用 `#AliasNoIntersection` 试图将默认规则中已无交的两个域声明为无交。 | `#AliasNoIntersection(int, float)` （假设它们默认已弱互斥） | 补充规则只能收紧约束，不能放松。 |



### 小结：编译器何时会报错？

总结来说，编译器在处理本别名模型时，会在以下两类主要情况下报错：

1.  **模型定义不合法**：包括但不限于抽象域树的结构性问题（如重名、未定义引用）和规则本身的语法错误。这类错误在编译初期即可发现，必须由程序员修正。
2.  **规则逻辑冲突**：试图通过补充规则放松默认的、更严格的别名关系（例如，强制让两个互斥的域相交）。这违反了系统设计的“保守性”基本原则，编译器不应接受。

通过以上的错误处理规定，可以确保别名模型信息在源头上是正确和一致的，为后续的别名分析和优化奠定可靠的基础。


# 文法规则伪代码


## 1. 抽象域树定义文法

```
// 抽象域树定义部分
Program ::= (AliasTreeDefinition | AliasNoIntersection)*

AliasTreeDefinition ::= "#AliasTree" "(" NodeName "," ParentNode "," Attribute ")" 

NodeName ::= Identifier
ParentNode ::= Identifier
Attribute ::= "Exclusive" | "WeakExclusive" | "WeakInclusive" | "Inclusive"

AliasNoIntersection ::= "#AliasNoIntersection" "(" NodeName "," NodeName ")"
```

## 2. 指针别名注解文法

```
// 指针别名注解部分（嵌入在变量声明中）
VariableDeclaration ::= TypeSpecifier AliasAnnotation? Identifier 

AliasAnnotation ::= "-!alias" "[" DomainExpression "]"
                   | "-!alias" "[" "]"  // 空规则体，表示根节点

DomainExpression ::= DomainTerm
                   | DomainExpression "||" DomainTerm

DomainTerm ::= DomainFactor
              | DomainTerm "&&" DomainFactor

DomainFactor ::= NodeName
               | "!" DomainFactor
               | "(" DomainExpression ")"

NodeName ::= Identifier  // 引用已定义的抽象域节点
```

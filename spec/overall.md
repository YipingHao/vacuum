# Vacuum 虚拟层指令规范

## 规范

### 字节序

默认为小端，物理指令集应当选择小端为默认选项。需要大端的场景则提供额外的虚拟指令。

### 最小可寻址单元

1字节。

### 访存连续性（Memory Consistency）

虚拟层指令的访存连续性模型为弱一致性。具体的模型详见访存指令部分。

规范并不禁止物理层使用更为严格的访存连续性模型。

### Vacuum 汇编语言的默认字符编码格式

虚拟层指令的写成的汇编语言的编码格式强制为 UTF-8（8-bit Unicode Transformation Format）

物理层指令如果有汇编语言，没有强制的编码格式要求。

#### 换行符格式

必须支持Linux系统默认的 LF（Line Feed，换行）格式), 其中字符编码为 '\n'（ASCII 码 10）。

不禁止其余的换行符格式，但也不强制支持。








## 虚拟指令

虚拟指令分为虚拟基本指令，虚拟拓展指令。虚拟扩展指令分为标准拓展指令，自定义拓展指令，社区认证扩展指令

物理指令集中某些元素构成的子集合的进一步组合，必须支持基本全部虚拟指令的功能。但是并不强制虚拟指令到物理指令集中指令的一对一的翻译。只要实现了所约定的功能和行为，无论实现方式如何，均不违反Vacuum的规范。

### 虚拟基本指令

其中，虚拟基本指令是本指令集的最基本的模块，虚拟基本指令，在功能上不是绝对独立的，比如可以用虚拟基本指令的整数加法与位移操作实现虚拟基本指令中的乘法指令对应的操作。但是Vacuum标准并不提供不独立的虚拟基本指令之间的相互模拟实现的过程。如果物理指令集和伴随式编译解释器无法提供某些虚拟基本指令到物理指令的一对一翻译，并不违反规范，但是要自行解决使用物理指令集中指令的某个子集合组合模拟实现全部的虚拟基本指令。

### 虚拟扩展指令

虚拟扩展指令分为标准拓展指令，自定义拓展指令，社区认证扩展指令。它们的区别在于标准扩展指令是Vacuum标准的一部分，自定义扩展指令和社区认证扩展指令不是。虚拟自定义扩展指令可以由任意使用Vacuum指令集的法律实体进行符合规范的任意的定义。社区认证扩展指令是用户自定义指令，提交到某个关于Vacuum的社区后经由社区认证的自定义扩展指令。


# Vacuum汇编语言文件

## 标识符与类型名 

### 标识符

Vacuum 承认的标识符格式和C语言类似但是不完全相同。Vacuum 承认的标识符格式没有关键字禁用和长度限制。

Vacuum 标识符的格式（命名规则）是严格规定的，必须遵守以下规则，否则会导致编译错误：

1. **组成字符**：只能由字母（A-Z、a-z）、数字（0-9）、下划线（_）三种字符组成，不能包含其他特殊字符（如空格、$、@、#、-等）。  
   示例：`abc`、`num123`、`_value` 是合法的；`a-b`、`123var`、`var$` 是非法的。

2. **首字符限制**：第一个字符必须是 **字母或下划线**，不能以数字开头。  
   示例：`age`、`_count` 是合法的；`1st`、`2name` 是非法的。

3. **大小写敏感**：C语言区分大小写字母，因此大小写不同的标识符会被视为不同的名称。Vaccum与之相同。  
   示例：`sum`、`Sum`、`SUM` 是三个不同的标识符。

4. **关键字禁用**：是Vacuum没有关键字的概念，所有的起到关键字作用的东西开头都有特殊符号表明它的开始比如`#end`。  

5. **长度限制**：Vacuum标准不限制标识符的长度。

### 类型名

合法的类型名称的格式接近C++中类型的格式，这种相对高级别的格式是为了汇编代码的人类可读性和高级语言向下Vacuum虚拟层编译的方便与统一，的文法规则伪代码如下:

```
unit: {
    Type: type;
    Const: const;
}
type: {
    single: complex;
    null: complex "<"  ">";
    nontrival: complex "<" list ">";
}
list:{
    single: unit;
    multi: list "-" unit;
}
complex:{
    single: id;
    multi: complex "::" id;
}

```




Vacuum指令集构成汇编代码文件可以被视为一种特殊的目标文件。它可以由很多个相同格式的Vacuum指令集构成汇编代码文件链接成一个新的相同格式的Vacuum代码文件。汇编语言文件有N种不同的段，并且在这些在代码中必须按照规范规定的顺序先后出现。这N种段分别是复合数据类型定义段；外部依赖声明段；扩展指令集段；可变数据段；常量段；代码段;

每一个段的开头需要用独占一行的段开头符号表明是开头，结尾则统一以独占一行的`#end`表示段的结尾。

段开头符号规定如下复合数据类型定义段:`#complex`；外部依赖声明段`#extern`；扩展指令集段`#instruct`；可变数据段`#data`；常量段`#const`；代码段`#code`;


# 数据类型与字面值

## 基本数据类型

基本数据类型，一共有六种分别是，布尔型，有符号整型，无符号整型，浮点型，复数型，自由型。

### 1 布尔型
布尔型变量对应数据关键字bool。它有自身一种子类型。

### 2 有符号整型

有符号整型对应关键字`sint`。有符号整型强制采取补码格式存储，与无符号整型的子类型体系保持严格一致，同样包含八种子类型以适配不同位宽需求：
`sint8`对应 8bit 有符号整数（取值范围 $- 2^{7}\sim 2^{7}-1$）；
`sint16`对应 16bit 有符号整数（取值范围 $- 2^{15}\sim 2^{15}-1$）；
`sint32`对应 32bit 有符号整数（取值范围 $- 2^{31}\sim 2^{31}-1$）；
`sint64`对应 64bit 有符号整数（取值范围 $- 2^{63}\sim 2^{63}-1$）；
`sint128`对应 128bit 有符号整数（取值范围 $- 2^{127}\sim 2^{127}-1$）；
`sint`单独作为 “机器字长有符号整数” 的关键字，其位宽与当前硬件的机器字长（如 32 位 CPU/GPU 为 32bit，64 位硬件为 64bit）保持一致，适配硬件原生位宽运算场景；
`sintH`对应机器字长一半的有符号整数（如 64 位硬件中为 32bit，32 位硬件中为 16bit）；
`sintD`对应机器字长一倍的有符号整数（如 64 位硬件中为 128bit，32 位硬件中为 64bit）。

### 3 无符号整型

无符号整型对应关键字`uint`。无符号整型与有符号整型的子类型体系保持严格一致，同样包含八种子类型以适配不同位宽需求：  
`uint8`对应8bit无符号整数（取值范围$0\sim 2^8-1$）；
`uint16`对应16bit无符号整数（取值范围$0\sim 2^{16}-1$)；
`uint32`对应32bit无符号整数（取值范围$0\sim 2^{32}-1$）；
`uint64`对应64bit无符号整数（取值范围$0\sim 2^{64}-1$）；
`uint128`对应128bit无符号整数（取值范围$0\sim 2^{128}-1$）；  
`uint`单独作为“机器字长无符号整数”的关键字，其位宽与当前硬件的机器字长（如32位CPU/GPU为32bit，64位硬件为64bit）保持一致，主要用于地址计算、位掩码操作等需匹配硬件原生位宽的场景；  
`uintH`对应机器字长一半的无符号整数（如64位硬件中为32bit，32位硬件中为16bit）；  
`uintD`对应机器字长一倍的无符号整数（如64位硬件中为128bit，32位硬件中为64bit）。

### 4 浮点型

浮点型对应关键字`float`。浮点型遵循 IEEE 754-2008 规范，与整型子类型体系保持位宽兼容性，包含五种子类型：
`float16`对应 16bit 半精度浮点（1 位符号位、5 位指数位、10 位尾数位）；
`float32`对应 32bit 单精度浮点（1 位符号位、8 位指数位、23 位尾数位）；
`float64`对应 64bit 双精度浮点（1 位符号位、11 位指数位、52 位尾数位）；
`float128`对应 128bit 四精度浮点（预留扩展接口，适配高精度科学计算场景）；
`float`单独作为 “硬件性能最优精度浮点” 的关键字，默认映射为当前硬件效率最高的精度（如 GPU 优先 `float32`，高精度 CPU 场景默认 `float64`），由编译器结合硬件特性自动选择。

### 5 复数型

复数型对应关键字`complex`。复数型子类型与浮点型位宽严格对齐，确保类型体系一致性，包含五种子类型：
`complex32`总位宽 32bit（通常由两个 float16 组成，分别表示实部与虚部）；
`complex64`总位宽 64bit（通常由两个 float32 组成）；
`complex128`总位宽 128bit（通常由两个 float64 组成）；
`complex256`总位宽 256bit（通常由两个 float128 组成）；
`complex`作为默认位宽复数类型，其总位宽为float默认类型的两倍（如 `float` 默认 `float32` 时，`complex` 对应 `complex64`），确保与浮点型默认精度的运算兼容性。

### 6 自由型

无类型对应关键字`void`。无类型子类型需显式指定位宽，共九种子类型，覆盖 1~256bit 及硬件相关位宽场景：
`void8`对应 8bit 无类型数据；
`void16`对应 16bit 无类型数据；
`void32`对应 32bit 无类型数据；
`void64`对应 64bit 无类型数据；
`void128`对应 128bit 无类型数据；
`void256`对应 256bit 无类型数据；
`void`作为 “机器字长无类型” 关键字，其位宽与当前硬件机器字长一致（如 64 位硬件中为 64bit）；
`voidH`对应机器字长一半的无类型数据（如 64 位硬件中为 32bit，32 位硬件中为 16bit）；
`voidD`对应机器字长一倍的无类型数据（如 64 位硬件中为 128bit，32 位硬件中为 64bit）。
所有无类型子类型均支持参与任意基础运算（加法、位运算等），编译器不进行类型语义校验，运算逻辑仅依赖位宽与二进制值，适用于无明确语义的二进制数据处理场景（如加密数据片段、自定义协议数据包）。


## 字面值

Vacuum中定义的标量字面值的有如下几种类型。布尔型，十进制有符号型，十进制无符号型，二进制型，十六进制型，浮点型，以及地址型。所有类型均需要使用反引号包裹开头和结束，反引号的包裹中不能有空格。例如 ` \`true \` `是不合法的。

## 机器字面值

Vacuum 虚拟层指令定义了一系列的物理参数字面值，成为机器字面值，这些字面值的具体数值均为无符号整型或者布尔型在vacuum虚拟指令层并没有被固定。但是有可能会给出它的限制。
机器字面值分为关键机器字面值和普通机器字面值。区别是关键机器字面值对编译解释流程有巨大的作用。而普通机器子字面值没有。每一个物理指令集都应该给出全体机器字面值的具体数值。

### 机器字长

对应标识符`WordLength`。是一个关键机器字面值，无符号整型。在不高于64的情况下可以是16，32，64。高于64的情形是规范的留白。在虚拟指令集中不引入机器字长，于兼容性有利。但是此时由于不知道机器字长，复合数据类型的内存排布方式无法在Vacuum层得知。

### SIMD宽度

对应标识符`SIMDWidth`。是一个关键机器字面值，无符号整型。必须是4乘以2的正整数幂次或者零，不得大于机器字长。比如64位机器上可许宽度是0，8，16，32，64。

### SIMD宽度对数 

是一个关键机器字面值，无符号整型。如果SIMD宽度是0,那么它也是0，否则它是SIMD宽度的以2为底的对数。比如64位机器上可许宽度是0，1，2，3，4，5，6。

### 簇容量 

是一个关键机器字面值，无符号整型。但必须是1或者2的正整数幂次，不得大于机器字长。比如64位机器上可许宽度是1，2，4，8，16，32，64。

### 簇容量对数 

是一个关键机器字面值，无符号整型。是簇容量的以2为底的对数。比如64位机器上可许宽度是0，1，2，3，4，5，6。

### 二阶簇容量

是一个关键机器字面值，无符号整型。必须是1,2,4,8中的一个。

## 变量

Vacuum运算的操作数是变量。变量分为寄存器变量和栈中量。这两个变量的区别是寄存器变量没有分配任何的内存地址，没有操作可以获得它的内存中地址。而栈中变量则会被分配内存中的地址，存在操作可以获得它的地址。但是寄存器变量在向物理指令集转化时并不保证一定被分配给某一个寄存器，而栈中变量也不保证一定被分配在栈中，也有可能被编译器优化后分配给一个寄存器。寄存器变量的关键字是`reg`而栈中变量的关键字是`stack`。

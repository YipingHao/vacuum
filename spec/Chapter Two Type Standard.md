# 数据类型与字面值

## 基本数据类型

基本数据类型，一共有六种分别是，布尔型，有符号整型，无符号整型，浮点型，复数型，自由型。其中有符号整型强制采取补码格式存储。

### 1 布尔型
布尔型变量对应类型名`<bool>`。它有自身一种子类型。

### 2 有符号整型

有符号整型对应类关键字`sint`。有符号整型强制采取补码格式存储，与无符号整型的子类型体系保持严格一致，同样包含八种子类型以适配不同位宽需求：
- `<sint8>`对应 8bit 有符号整数（取值范围 $- 2^{7}\sim 2^{7}-1$）；
- `<sint16>`对应 16bit 有符号整数（取值范围 $- 2^{15}\sim 2^{15}-1$）；
- `<sint32>`对应 32bit 有符号整数（取值范围 $- 2^{31}\sim 2^{31}-1$）；
- `<sint64>`对应 64bit 有符号整数（取值范围 $- 2^{63}\sim 2^{63}-1$）；
- `<sint128>`对应 128bit 有符号整数（取值范围 $- 2^{127}\sim 2^{127}-1$）；
- `<sint>`单独作为 “机器字长有符号整数” 的关键字，其位宽与当前硬件的机器字长（如 32 位 CPU/GPU 为 32bit，64 位硬件为 64bit）保持一致，适配硬件原生位宽运算场景；
- `<sintH>`对应机器字长一半的有符号整数（如 64 位硬件中为 32bit，32 位硬件中为 16bit）；
- `<sintD>`对应机器字长一倍的有符号整数（如 64 位硬件中为 128bit，32 位硬件中为 64bit）。

### 3 无符号整型

无符号整型对应`uint`。无符号整型与有符号整型的子类型体系保持严格一致，同样包含八种子类型以适配不同位宽需求：

- `<uint8>`对应8bit无符号整数（取值范围$0\sim 2^8-1$）；
- `<uint16>`对应16bit无符号整数（取值范围$0\sim 2^{16}-1$)；
- `<uint32>`对应32bit无符号整数（取值范围$0\sim 2^{32}-1$）；
- `<uint64>`对应64bit无符号整数（取值范围$0\sim 2^{64}-1$）；
- `<uint128>`对应128bit无符号整数（取值范围$0\sim 2^{128}-1$）；  
- `<uint>`单独作为“机器字长无符号整数”的关键字，其位宽与当前硬件的机器字长（如32位CPU/GPU为32bit，64位硬件为64bit）保持一致，主要用于地址计算、位掩码操作等需匹配硬件原生位宽的场景；  
- `<uintH>`对应机器字长一半的无符号整数（如64位硬件中为32bit，32位硬件中为16bit）；  
- `<uintD>`对应机器字长一倍的无符号整数（如64位硬件中为128bit，32位硬件中为64bit）。

### 4 浮点型

浮点型对应`float`。浮点型遵循 IEEE 754-2008 规范，与整型子类型体系保持位宽兼容性，包含六种子类型：
- `<float16>`对应 16bit 半精度浮点（1 位符号位、5 位指数位、10 位尾数位）；
- `<float32>`对应 32bit 单精度浮点（1 位符号位、8 位指数位、23 位尾数位）；
- `<float64>`对应 64bit 双精度浮点（1 位符号位、11 位指数位、52 位尾数位）；
- `<float128>`对应 128bit 四精度浮点（预留扩展接口，适配高精度科学计算场景）；
- `<float>`单独作为 “硬件性能最优精度浮点” 的关键字，默认映射为当前硬件效率最高的精度（如 GPU 优先 `<float32>`，高精度 CPU 场景默认 `<float64>`），由编译器结合硬件特性自动选择。
- `<floatM>`单独作为 “机器字长浮点数” 的关键字，默认映射为当前硬件机器字长长度对应的精度。

### 5 复数型

复数型对应类型名`complex`。复数型子类型与浮点型位宽严格对齐，确保类型体系一致性，包含六种子类型：
- `<complex32>`总位宽 32bit（通常由两个 float16 组成，分别表示实部与虚部）；
- `<complex64>`总位宽 64bit（通常由两个 float32 组成）；
- `<complex128>`总位宽 128bit（通常由两个 float64 组成）；
- `<complex256>`总位宽 256bit（通常由两个 float128 组成）；
- `<complex>`作为默认位宽复数类型，其总位宽为float默认类型的两倍（如 `<float>` 默认 `<float32>` 时，`<complex>` 对应 `<complex64>`），确保与浮点型默认精度的运算兼容性。
- `<complexM>`单独作为 “机器字长浮点数一倍宽度的复数” 的关键字，默认映射为当前硬件机器字长度一倍对应的精度。（如64位硬件中为128bit，32位硬件中为64bit）

### 6 自由型

自由型对应类型名`binary`。无类型子类型需显式指定位宽，共九种子类型，覆盖 1~256bit 及硬件相关位宽场景：
- `<binary8>`对应 8bit 无类型数据；
- `<binary16>`对应 16bit 无类型数据；
- `<binary32>`对应 32bit 无类型数据；
- `<binary64>`对应 64bit 无类型数据；
- `<binary128>`对应 128bit 无类型数据；
- `<binary256>`对应 256bit 无类型数据；
- `<binary>`作为 “机器字长无类型” 关键字，其位宽与当前硬件机器字长一致（如 64 位硬件中为 64bit）；
- `<binaryH>`对应机器字长一半的无类型数据（如 64 位硬件中为 32bit，32 位硬件中为 16bit）；
- `<binaryD>`对应机器字长一倍的无类型数据（如 64 位硬件中为 128bit，32 位硬件中为 64bit）。
所有无类型子类型均支持参与任意基础运算（加法、位运算等），编译器不进行类型语义校验，运算逻辑仅依赖位宽与二进制值，适用于无明确语义的二进制数据处理场景（如加密数据片段、自定义协议数据包）。


## 字面值

Vacuum中定义的标量字面值的有如下几种类型。布尔型，整数型，浮点型，复数型，机器符号量。所有类型均需要使用反引号包裹开头和结束，反引号的包裹中不能有空格。例如 `` `true ` ``是不合法的,而`` `true` ``是合法的。字面值并不存在位宽的概念，但是当它参与运算的时候有向特定的基本数据类型转化的规则。字面值不提供任何字面值之间的运算语义。换言之不能用两个字面值运算算出另一个新的字面值。但是字面值可以转换成符号量参与运算。

### 布尔型

布尔型合法的标量字面值有如下两种类型`` `true` ``，`` `false` ``其余的字符比如`` `T` ``，`` `True` ``等均不被承认。


### 整数型

整数型有五种表示方法，分别是十进制有符号型格式、十进制无符号型格式、二进制格式、十六进制格式、八进制格式，其中只有十进制有符号格式被认为是有符号类型的整数。除了十进制有符号型格式，其余都视为无符号型格式，具体格式规则如下：

1. **十进制有符号型格式**  
   - 由数字 `0-9` 组成，可带正负号（`+` 可省略，`-` 表示负数）  
   - 不能以 `0` 开头（除非值为 `0` 本身）  
   - 示例：`` `123` ``、`` `-456` ``、`` `0` ``（合法）；`` `012` ``（不合法，会被解析为八进制）、`` `12a3` ``（不合法，含非数字字符）  

2. **十进制无符号型格式**  
   - 在十进制有符号格式基础上，末尾添加 `u` 或 `U` 后缀  
   - 不能带负号（无符号类型不支持负数）  
   - 示例：`` `123u`、`` `456U` ``、`` `0U` ``（合法）；`` `-789u` ``（不合法，无符号类型不能带负号）  

3. **二进制格式**  
   - 以 `0b` 或 `0B` 为前缀，后跟数字 `0-1`  
   - 默认为无符号类型，**不支持添加 `u`/`U` 后缀**  
   - 示例：`` `0b1010` ``、`` `0B1111` ``（合法）；`` `0b101u` ``（不合法，二进制格式不允许后缀）、`` `0b2` ``（不合法，含非二进制数字）  

4. **十六进制格式**  
   - 以 `0x` 或 `0X` 为前缀，后跟数字 `0-9` 及字母 `a-f`/`A-F`（不区分大小写）  
   - 默认为无符号类型，**不支持添加 `u`/`U` 后缀**  
   - 示例：`` `0x1a` ``、`` `0X3F` ``（合法）；`` `0xabC U` ``（不合法，含空格）、`` `0xG` ``（不合法，含非十六进制字符）、`` `0x12u` ``（不合法，十六进制格式不允许后缀）  

5. **八进制格式**  
   - 以 `0o` 或 `0O` 为前缀（区别于十进制，明确标注八进制），后跟数字 `0-7`  
   - 默认为无符号类型，**不支持添加 `u`/`U` 后缀**  
   - 示例：`` `0o12` ``（对应十进制 10）、`` `0O77` ``（对应十进制 63）（合法）；`` `0o8` ``（不合法，含非八进制数字）、`` `0o5U` ``（不合法，八进制格式不允许后缀）  


所有整数型字面值必须用反引号包裹，且内部无空格，例如：  
- 合法：`` `123` ``、`` `-456u` ``、`` `0b101` ``、`` `0xabc` ``、`` `0o77` ``  
- 不合法：`` ` 123 ` ``（含空格）、`` `0x g` ``（含空格）、`` `-0b11` ``（二进制格式不能带负号）、`` `0x12u` ``（十六进制格式带后缀）  

当整数型字面值参与运算时，会根据运算上下文自动转换为相应位宽的基本数据类型，转换规则遵循 Vacuum 汇编的类型转换规范。

### 浮点型



浮点型字面值分为**异常浮点字面值**和**浮点正常值**，所有浮点型字面值均需用反引号包裹，内部无空格，且不区分大小写（如`inf`与`INF`等效）。字面值本身不绑定位宽，参与运算时根据上下文自动转换为`<float16>`/`<float32>`/`<float64>`/`<float128>`或默认`<float>`类型，转换规则规则转换规则遵循Vacuum汇编的类型转换规范。


#### 1. 异常浮点字面值（5种，遵循IEEE 754规范）
异常浮点异常浮点字面值用于表示无意义或超出常规范围的浮点结果，共5种固定表示形式，所有浮点子类型（`float16`/`float32`等）通用：

- 正无穷大：用`` `inf` ``或`` `infinity` ``表示，对应运算结果超出当前精度最大有限值的场景（如`1.0 / 0.0`）。合法示例为`` `inf` ``、`` `INFINITY` ``；不合法示例如`` ` inf` ``（包含前导空格）。
  
- 负无穷大：用`` `-inf` ``或`-infinity` ``表示，对应运算结果超出当前精度最小有限值的场景（如`-1.0 / 0.0`）。合法示例为`` `-inf` ``、`` `-Infinity` ``；不合法示例如`` `- inf` ``（符号后带空格）。
  
- 非数（标准NaN）：用`` `nan` ``表示，对应无效运算的结果（如`0.0 / 0.0`、`sqrt(-1.0)`），不区分正负。合法示例为`` `nan` ``、`` `NAN` ``；不合法示例如`` `nan123` ``（包含多余字符）。
  
- signaling NaN：用`` `snan` ``表示，是特殊非数，会触发“无效操作”异常（用于调试或特殊场景，需硬件支持）。合法示例为`` `snan` ``、`` `SNAN` ``；不合法示例如`` `s nan` ``（包含空格）。
  
- quiet NaN：用`` `qnan` ``表示，是特殊非数，不触发异常（用于传递“无效值”状态，避免运算中断）。合法示例为`` `qnan` ``、`` `QNAN` ``；不合法示例如`` `qn_an` ``（包含非法分隔符）。

注：`` `snan` ``与`` `qnan` ``仅在硬件支持IEEE 754扩展异常机制时生效，若硬件不支持，会自动降级为标准`nan`。


#### 2. 浮点正常值（2种表示格式）
浮点正常值用于表示常规范围内的有限浮点数，提供两种格式以平衡“易读性”与“二进制转换严格性”：


##### 格式1：十进制风格格式（接近C语言，易读性强）
基于“十进制尾数 + 十进制指数”的表示方式，兼容日常数值书写习惯，适合人工输入与可读性场景；需注意：十进制小数向二进制浮点转换可能存在精度损失（如`0.1`无法用二进制浮点精确表示）。

格式规则如下：
- 由“十进制尾数”和可选的“十进制指数”组成，指数部分用`e`或`E`分隔。
- 尾数部分需包含以下至少一种元素：数字`0-9`、小数点`.`（小数点前后至少有一位数字）。
- 可带正负号（`+`可省略，`-`需写在最前面）。
- 不允许冗余前导零（如`00123.45`不合法，需写为`123.45`；但`0.123`、`123.0`合法）。

具体场景示例：
- 带小数点（无指数）：尾数含`.`，无指数部分。合法示例为`` `123.45` ``、`` `-0.678` ``；不合法示例如`` `123.` ``（小数点后无数字）、`` `.456` ``（小数点前无数字）。
  
- 无小数点（有指数）：尾数为整数，含`e/E`及指数（指数可带正负）。合法示例为`` `123e4` ``（即123×10⁴）、`` `-456E-7` ``（即-456×10⁻⁷）；不合法示例如`` `123e` ``（指数后无数字）、`` `e45` ``（指数前无尾数）。
  
- 带小数点+指数：尾数含`.`，且含`e/E`及指数。合法示例为`` `123.45e6` ``（即123.45×10⁶）、`` `-0.789E-2` ``（即-0.789×10⁻²）；不合法示例如`` `123.e4` ``（小数点后无数字）、`` `012.34e5` ``（冗余前导零）。



##### 格式2：八进制指数-尾数格式（基于`0F`前缀，纯整数尾数）
采用“八进制整数尾数 + 八进制指数”的表示方式，尾数为纯整数（无小数部分），通过指数明确控制数值缩放，前缀`0F`（或`0f`）标识浮点类型，保持八进制到二进制的严格映射，无精度损失。

**格式规则**：  
- 固定以`0F`或`0f`为前缀（`F`代表浮点，与整数格式`0o`/`0x`区分）。  
- 前缀后接“八进制整数尾数”和“八进制指数”，指数部分用`p`或`P`分隔（不可省略，确保与整数字面值区分）。  
- 八进制整数尾数由纯八进制数字`0-7`组成（至少1位数字），可带正负号（`-`写在`0F`/`0f`后，如`0F-123p6`；`+`可省略）。  
- 尾数不允许冗余前导零（如`0F012p5`不合法，需写为`0F12p5`；但`0F0p0`合法，表示零值）。  
- 八进制指数由纯八进制数字`0-7`组成，可带正负号（`+`可省略，`-`需写在指数前，如`0F123p-2`），表示“2的指数次幂”。  

**核心逻辑**：  
- 八进制整数尾数直接转换为二进制整数（1位八进制→3位二进制，如`0F12p3`中，尾数`12`→二进制`1010`）。  
- 八进制指数转换为十进制后，作为“2的幂次”（如`p6`→2⁶，`p-3`→2⁻³）。  
- 最终数值 = 二进制尾数（整数） × 2^（八进制指数转换的十进制值），通过指数调整小数点位置，替代原尾数中小数点的功能。  

**示例与解析**：  
- `` `0F12p4` ``：前缀`0F`，尾数`12`（八进制）→二进制`1010`（十进制10）；指数`4`（八进制）→十进制4；数值=10 × 2⁴=160（二进制`10100000`），合法。  
- `` `0f-45p-2` ``：前缀`0f`，符号`-`，尾数`45`（八进制）→二进制`100101`（十进制37）；指数`-2`（八进制）→十进制-2；数值=-37 × 2⁻²=-37/4=-9.25，合法。  
- `` `0F0p0` ``：尾数`0`（八进制），指数`0`（八进制）；数值=0 × 2⁰=0，合法（表示浮点零）。  
- `` `0F123` ``：无指数部分（缺少`p/P`及指数值），不合法（无法与八进制整数字面值区分）。  
- `` `0F012p5` ``：尾数含冗余前导零（`012`应写为`12`），不合法。  
- `` `0F12p q4` ``：指数部分含空格，不合法。  
- `` `0F12.3p4` ``：尾数含小数点（违反纯整数要求），不合法。  

此设计通过“纯整数尾数+指数缩放”完全替代了小数点的功能，避免了语义冲突，同时保留了八进制到二进制的严格映射特性，适合底层精确浮点运算场景。


### 复数型

复数型字面值用于表示由“实部”和“虚部”组成的复数，暂未定义异常值，仅支持正常复数表示。提供两种风格的字面值格式，均需用反引号包裹，内部无空格，且实部、虚部的格式需分别遵循浮点型字面值中对应风格的规则（十进制风格/八进制指数-尾数风格）。字面值本身不绑定位宽，参与运算时根据上下文上下文自动转换为`<complex32>`/`<complex64>`/`<complex128>`/`<complex256>`或默认`<complex>`类型（与浮点型默认精度匹配），转换规则遵循 Vacuum 汇编的类型转换规范。

两种格式中，虚部均需通过后缀`I`或`i`标识（不区分大小写，`I`与`i`等效），实部与虚部之间用逗号分隔，且实部、虚部均为合法浮点正常值（不可省略，若某部分为0需显式写`0`对应的浮点格式）。


#### 1. 格式1：十进制风格复数（易读性强，兼容日常书写）
实部与虚部均采用浮点型的“十进制风格格式”（即十进制尾数+可选十进制指数，参考浮点型格式1），适合人工输入与可读性优先的场景，需注意十进制转二进制可能存在的精度损失（与浮点型十进制风格一致）。

**格式规则**：  
- 整体结构为`[实部],[虚部][I/i]`，其中：  
  - 实部：需符合浮点型十进制风格格式（如`123.45`、`-67.8e9`、`0`）；  
  - 虚部：需符合浮点型十进制风格格式（如`98.76`、`-5.4E-3`、`0`），且末尾必须加`I`或`i`标识虚部属性；  
- 实部、虚部均不可省略，即使值为0也需显式写`0`（如`0,0I`，不可写为`,0i`或`0,I`）；  
- 实部与虚部之间仅允许单个逗号分隔，无空格，且逗号前后无多余字符。

**示例与解析**：  
- `` `123.45,67.8i` ``：实部`123.45`（十进制浮点），虚部`67.8`（十进制浮点）+`i`，表示复数 `123.45 + 67.8i`，合法。  
- `` `-0.78e3,9.0E-2I` ``：实部`-0.78e3`（即-780.0），虚部`9.0E-2`（即0.09）+`I`，表示复数 `-780.0 + 0.09i`，合法。  
- `` `0,0i` ``：实部`0`，虚部`0`+`i`，表示复数 `0 + 0i`（复数零），合法。  
- `` `123,45.6e2I` ``：实部`123`（无小数点，十进制浮点），虚部`45.6e2`（即4560.0）+`I`，表示复数 `123 + 4560.0i`，合法。  
- `` `123.45 , 67.8i` ``：实部与虚部之间含空格，不合法。  
- `` `123.45,67.8` ``：虚部无`I/i`后缀，不合法。  
- `` `,0i` ``：实部省略，不合法。  


#### 2. 格式2：八进制指数-尾数风格复数
实部与虚部均采用浮点型的“八进制指数-尾数格式”（即`0F`前缀+八进制整数尾数+八进制指数`p`，参考浮点型格式2），实部、虚部分别通过`0F`前缀标识，虚部额外加`I`或`i`后缀，完全避免十进制转二进制的精度损失，适合底层高精度复数运算场景。

**格式规则**：  
- 整体结构为`[实部（0F格式）],[虚部（0F格式）][I/i]`，其中：  
  - 实部：需符合浮点型八进制指数-尾数格式（即`0F`/`0f`前缀+八进制整数尾数+`p`+八进制指数，如`0F12p4`、`0f-45p-2`、`0F0p0`）；  
  - 虚部：需符合浮点型八进制指数-尾数格式，且末尾必须加`I`或`i`后缀（如`0F34p5I`、`0f-67p-3i`、`0F0p0I`）；  
- 实部、虚部均不可省略，即使值为0也需显式写`0F0p0`（如`0F0p0,0F0p0i`）；  
- 实部与虚部之间仅允许单个逗号分隔，无空格，且实部、虚部各自的`0F`格式需完整（不可省略`p`及指数）。

**核心逻辑**：  
实部、虚部分别按浮点型八进制格式转换为二进制浮点值（如实部`0F12p4`→160.0，虚部`0F34p2I`→`0F34p2`对应的数值+`i`），最终复数为“实部数值 + 虚部数值×i”，全程无精度损失。

**示例与解析**：  
- `` `0F12p4,0F34p2i` ``：实部`0F12p4`（八进制格式，对应160.0），虚部`0F34p2`（八进制格式，`0F34p2`→八进制尾数`34`=十进制28，指数`2`→2²=4，即28×4=112.0）+`i`，表示复数 `160.0 + 112.0i`，合法。  
- `` `0f-45p-2,0F67p3I` ``：实部`0f-45p-2`（对应-9.25），虚部`0F67p3`（八进制尾数`67`=十进制55，指数`3`→8，即55×8=440.0）+`I`，表示复数 `-9.25 + 440.0i`，合法。  
- `` `0F0p0,0f0p0i` ``：实部`0F0p0`（0.0），虚部`0f0p0`（0.0）+`i`，表示复数 `0 + 0i`，合法。  
- `` `0F12p4,0F34I` ``：虚部缺少`p`及指数（违反八进制格式要求），不合法。  
- `` `0F12,0F34p2i` ``：实部缺少`p`及指数（违反八进制格式要求），不合法。  
- `` `0F12p4 , 0F34p2I` ``：实部与虚部之间含空格，不合法。


## 复合数据类型

复合数据类型分为指针型，结构体与共用体。它们在定义之前必须指定类型名。

### 类型名

Vacuum中所有类型名称必须用`<`和`>`包裹，包括基础类型与用户自定义复合类型。类型名格式设计兼顾人类可读性与编译便利性，其文法规则伪代码如下：

```
unit: {
    Type: type;          // 类型单元（如<id>）
    Const: const;        // 常量修饰单元（如'0xFF'）
}
type: {
    single: "<" complex ">";               // 单类型（如<int>、<ns::Struct>）
    null: "<" complex "<"  ">" ">";        // 空参数类型（如<list<>>）
    nontrival: "<" complex "[" list "]" ">"; // 带参数类型（如<array[<int>,5]>）
}
list: {
    single: unit;        // 单元素列表（如<str>）
    multi: list "," unit; // 多元素列表（如<id,<int>,'3'>）
}
complex: {
    single: id;          // 单标识符（如int、MyStruct）
    multi: complex "::" id; // 命名空间嵌套（如std::vector）
}
```

*说明*：  
- `id` 表示标识符（字母、数字、下划线组成，首字符非数字）  
- 常量单元需用单引号包裹（如`'0x100'`、`'true'`）  





### 结构体

#### 1. 定义整体结构
结构体定义以`#struct`为起始，需显式指定两个正交维度的布局关键字，完整语法框架：

```
#struct [顺序关键字] [填充关键字] <结构体类型名> {
    [成员定义列表]
}
```

- 必须包含`#struct`关键字，不可省略  
- 顺序关键字与填充关键字为必选，二者顺序可互换  
- 关键字之间、关键字与结构体类型名之间、类型名与`{`之间允许任意空白字符（空格、制表符、换行）  


#### 2. 布局关键字（正交维度）
结构体布局由两个独立维度控制，共形成4种合法组合：

| 维度         | 关键字选项                          | 含义说明                                                                 |
|--------------|-----------------------------------|--------------------------------------------------------------------------|
| **成员顺序** | `#order(fixed)`                   | 成员严格按定义顺序布局，不允许编译器重排                                 |
|              | `#order(free)`                    | 允许编译器为优化（如对齐、紧凑性）自由重排成员顺序                       |
| **填充策略** | `#packing(padded)`                | 允许插入必要填充（满足硬件对齐）和优化性填充（提升访问效率）             |
|              | `#packing(compact)`               | 仅保留硬件强制要求的最小填充（通常为0），禁用所有非必要填充               |

*示例组合*：  
- `#order(fixed) #packing(padded)`：固定顺序+带填充（默认布局）  
- `#order(free) #packing(compact)`：自由重排+紧凑（内存敏感场景）  


#### 3. 结构体类型名规则
类型名需符合前述`type`文法，并包含布局元信息，格式特征：

- **核心标识**：由`complex`部分指定结构体名称，支持命名空间嵌套（如`<util::Buffer>`）  
- **模板参数**：通过`[list]`声明泛型参数，支持类型参数（如`<int>`）和常量参数（如`'1024'`）  
- **布局修饰符**：末尾需通过`-!order=xxx-!packing=xxx`显式声明布局，与前面的关键字严格一致  
  - 示例：`<RingBuffer[<uint>, '64']>-!order=fixed-!packing=compact`  


#### 4. 成员定义规则
结构体内部成员需遵循以下格式：

- **单成员格式**：`[类型名] [成员标识符];`  
  - 类型名：必须符合`type`文法（如`<float>`、`<!ptr[<ns::Data>]>`）  
  - 成员标识符：遵循`id`规则（字母、数字、下划线，首字符非数字）  
  - 必须以分号`;`结尾，不可省略  

- **类型修饰符**：支持通过`-!xxx`附加属性，常见修饰符：  
  - `!const`：常量成员（如`<!const-<int>>`表示常量整数）  
  - `!volatile`：易变成员（如`<!volatile-<ptr>>`表示易变指针）  
  - 修饰符需紧跟类型名，通过`-`连接  

- **成员列表**：多个成员以换行分隔，允许空行（仅作视觉分隔）  


#### 5. 特殊约束
- **禁止递归定义**：成员类型不能是当前正在定义的结构体（如`<Node>`不能包含`<Node>`类型成员）  
- **跨结构体引用**：可引用已定义的其他结构体（需使用完整类型名，如`<OtherStruct>`）  
- **布局一致性**：关键字与类型名修饰符必须一致（如`#order(free)`必须对应`-!order=free`，否则为语法错误）  
- **重排限制**：`#order(free)`模式下，编译器重排需保证成员对齐需求不低于`#packing`策略要求  


#### 示例解析
```
// 示例：自由重排+紧凑布局的缓冲区结构体
#struct #order(free) #packing(compact) <Buffer[<T>, 'MAX_SIZE']>-!order=free-!packing=compact {
    <!const-<uint>> capacity;  // 常量无符号整数：容量
    <uint> size;               // 无符号整数：当前大小
    <!ptr[<T>]> data;          // 指向T类型的指针：数据区
}
```

- **布局模式**：`#order(free)`（允许重排成员）+ `#packing(compact)`（仅必要填充），通过类型名末尾修饰符确认  
- **类型名解析**：  
  - 核心标识：`Buffer`  
  - 模板参数：类型参数`<T>`（泛型类型）、常量参数`'MAX_SIZE'`（编译期常量）  
- **成员类型**：包含常量类型（`<!const-<uint>>`）、基础类型（`<uint>`）和指针类型（`<!ptr[<T>]>`）  


此规则通过正交维度拆分布局控制，既保留了原类型名文法的灵活性，又使结构体布局语义更明确，覆盖更多优化场景。

## 符号量

符号量是指用符号表达的常量。

符号量与字面值有两个非常大的不同，

- 符号量的类型系统和用户定义的变量一致，因此可以参与运算，两个符号量通过运算的结果可以赋值给新的符号量。

- 符号量的取值固定的时间不同。字面值的取值固定时间在前端固定。处理虚拟目标文件的程序看到后立刻能知道它的取值。符号量则在中端后端和运行时固定。有一些符号量的值被固定是在中端，比如机器符号量，它的取值仅仅和物理指令集的的规定和集成电路的粗粒度参数确定,称为早期符号量。还有一些符号量的取值被固定在编译流程的晚期，比如某个函数的地址,称为晚期符号量。这两种符号量会有不同的格式，前者往往用`@`符号进行包裹，而后者使用`&`作为开头。符号量参与运算的规则一般等同于相应类型的字面值。

### 机器符号量

Vacuum 虚拟层指令定义了一系列的物理参数符号量，称为机器符号值。这些符号值参与运算时可以视为无符号整型或者布尔型的字面值，在vacuum虚拟指令层并没有固定具体的值。但是有可能会给出它的取值范围。这些机器符号量的格式类似于普通字面值，但是区别它使用反引号包裹了一个表示符。机器符号量分为关键机器符号量和普通机器符号量。区别是关键机器符号量对编译解释流程有巨大的作用。而普通机器符号量没有。每一个物理指令集都应该给出全体机器符号量的具体数值。

- 机器字长： 合法的形式是`` @WordLength@  ``。是一个关键机器符号量，无符号整型。在不高于64的情况下可以是16，32，64。高于64的情形是规范的留白。在虚拟指令集中不引入机器字长，于兼容性有利。但是此时由于不知道机器字长，复合数据类型的内存排布方式无法在Vacuum层得知。

- SIMD宽度：合法的形式是`` @SIMDwidth@  ``。是一个关键机器符号量，无符号整型。必须是4乘以2的正整数幂次或者零，不得大于机器字长。比如64位机器上可许宽度是0，8，16，32，64。

- SIMD宽度对数：合法的形式是`` @LogSIMDwidth@  ``。是一个关键机器符号量，无符号整型。如果SIMD宽度是0,那么它也是0，否则它是SIMD宽度的以2为底的对数。比如64位机器上可许宽度是0，1，2，3，4，5，6。

- 簇容量：合法的形式是`` @ClusterCapacity@  ``。是一个关键机器符号量，无符号整型。但必须是1或者2的正整数幂次，不得大于机器字长。比如64位机器上可许宽度是1，2，4，8，16，32，64。

- 簇容量对数： 合法的形式是`` @LogClusterCapacity@  ``。是一个关键机器符号量，无符号整型。是簇容量的以2为底的对数。比如64位机器上可许宽度是0，1，2，3，4，5，6。

- 二阶簇容量：合法的形式是`` @ClusterCapacity2@  ``。是一个关键机器符号量，无符号整型。必须是1,2,4,8中的一个。

- 局部共享存储器容量：合法的形式是`` @ShareMemCapacity@  ``。是一个关键机器符号量，无符号整型。必须是1024的非负整数倍数。是每个核心上物理可容纳的线程私有存储域的容量。
